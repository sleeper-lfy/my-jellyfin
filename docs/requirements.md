# Codex 开发任务：Windows 个人智能影音管理系统

## 一、你的角色与总体任务

你是一名资深 Windows 桌面应用架构师、全栈开发工程师、媒体播放器开发专家和专业 UI/UX 设计师。

请开发一款 Windows 本地运行的个人智能影音管理软件。

产品以 Jellyfin 的媒体库体验作为基础参考，但不是简单复制 Jellyfin。软件需要重点增强：

1. 智能媒体库管理与文件自动整理
2. 可扩展的第三方脚本刮削系统
3. 多条件搜索与不重复随机播放
4. 个性化影片推荐（猜你喜欢）
5. 自动发现刮削网站的新影片
6. 个人观影统计
7. 女演员墙与演员喜好排行
8. 高质量、现代化的 Windows 桌面 UI

**目标是实际开发、构建和验证一个可以使用的软件，而不是仅仅输出设计方案、静态页面或功能演示。**

如果当前工作目录已有项目，首先检查现有代码、构建方式和完成情况，尽量复用，避免直接覆盖。

---

## 二、首先进行技术方案选型

在正式开发前，对以下方案进行对比：

### 方案 A：Jellyfin 二次开发

研究 Jellyfin 服务端、Web 客户端、插件机制、媒体库管理及 Windows 运行方式。

重点判断：
- 是否适合单机 Windows 桌面软件
- 是否容易实现文件夹拖入、自动刮削和移动
- 是否方便扩展第三方刮削脚本
- 是否方便实现新片发现、随机队列和女演员墙
- 是否容易重构和美化 UI
- 后续升级 Jellyfin 的维护成本

### 方案 B：独立 Windows 桌面软件

使用成熟的开源播放器内核，例如 libmpv 或其他合适组件，不自行实现视频解码器。

重点判断：
- 媒体库扫描、管理和播放需要多少额外开发工作
- 本地文件拖拽、整理与移动的实现难度
- 第三方脚本插件的灵活程度
- UI 开发效率
- 安装、启动、运行性能及后续维护成本

### 选型原则

以总成本为优先，综合比较：

**首次开发成本＋后续维护成本＋扩展难度＋Windows 本地体验＋最终 UI 质量。**

本项目不需要优先考虑跨设备在线播放、NAS 服务部署和多用户服务端架构。

如果独立桌面方案在这些条件下更合适，可以不使用 Jellyfin。

完成分析后，将决策记录到 `docs/architecture-decision.md`，然后采用选定方案继续开发，不要只停留在方案比较阶段。

## 三、媒体库结构

媒体库分为三个主要类型：

### 1. 电影

电影采用智能媒体库模式。

支持：
- 自动识别影片
- 自动刮削元数据
- 海报墙
- PC 详情标题可选中复制；支持从剧照或缩略图指定海报 / 缩略图，提供居中、靠左、靠右裁切预览，无剧照时仍可用缩略图制作海报。
- PC 封面与大图支持左右方向键浏览；海报和缩略图显示大小独立可调并持久化，具体交互见 [UI 规范](ui-design.md)。
- 影片详情页
- 标签、年份、评分筛选
- 个人评分
- 收藏、想看、不感兴趣
- 随机播放
- 猜你喜欢
- 女演员墙
- 刮削来源及详情页跳转

### 2. 电视剧

采用「电视剧 → 季 → 集」层级管理。

支持：
- 自动识别电视剧、季数和集数
- 自动刮削电视剧资料
- 展示剧集海报与详情
- 按集播放、连续播放、播放进度保存
- 电视剧整体的个人评分
- 观影记录
- 参与猜你喜欢与随机播放

随机播放时，**一整部电视剧视为一个随机对象，而不是每一集分别参与抽取。**

随机选中电视剧后，默认从最近的未完成观看位置继续；没有记录时从第一集开始。剧内下一集播放与跳到随机队列下一部作品是两个不同操作。

### 3. 其他

用于非标准影视资料的视频，例如教程、收藏视频、个人视频等。

此类型采用文件夹层级管理。

要求：
- 保留原始文件夹及子目录结构
- 不进行联网刮削
- 不需要影视标签、演员、导演和评分等元数据
- **自动从视频中截取合适画面生成封面缩略图**
- 支持文件夹树形导航
- 支持带缩略图的文件浏览
- 支持文件名、文件夹名称搜索
- 支持视频播放与观看历史记录
- 支持参与随机播放

可以提供重新截取封面、手动选择视频画面等功能。

## 四、拖拽导入与文件自动整理

用户可以将 Windows 文件夹拖入对应媒体分区。

电影和电视剧的处理流程：

1. 扫描拖入的文件夹
2. 识别视频文件、字幕及相关附属文件
3. 解析文件名，提取可能的片名、年份、编号等
4. 根据当前分区的刮削配置执行信息匹配
5. 获取影片元数据与封面
6. 根据分区规则生成目标文件夹
7. 移动影片及其关联文件
8. 更新媒体库并生成影片卡片

对于“其他”类型：

- 不进行联网刮削
- 保留内部文件夹结构
- 按目标分区进行移动或导入
- 自动生成视频缩略图

异常处理要求：

- 识别失败进入待处理列表
- 匹配多个候选时允许用户确认
- 允许手动指定来源详情页并重新刮削
- 检测重复影片和同名文件
- 不得静默覆盖现有文件
- 文件移动失败可以恢复或重试
- 跨磁盘移动需保证文件完整后再删除原文件
- 导入任务有可查看的进度、结果及失败原因

支持用户手动修改刮削结果，并允许锁定字段，避免后续刷新覆盖。

## 五、第三方脚本刮削系统

**刮削网站由第三方脚本实现，不应将具体网站的解析逻辑写死在软件核心代码中。**

软件应提供统一的脚本插件规范。

插件可以选择实现：

- 搜索影片
- 根据详情页 URL 刮削
- 解析影片元数据
- 获取演员资料
- 获取海报等图片
- 抓取网站最新影片
- 获取指定分类的新收录内容

不是所有插件都必须支持全部功能。

软件应提供：

1. 插件安装、启用、禁用和卸载
2. 插件配置界面
3. 站点地址和分类路径配置
4. 刮削优先级设置
5. 刮削任务日志及错误提示
6. 单独的代理配置
7. 插件功能与权限说明

一个站点可以在不同分类下使用不同访问路径，共用同一个脚本。

第三方脚本应采用隔离执行和受控权限机制。插件主要负责元数据获取，不应默认具有任意删除用户文件的权限。

请提供清晰的插件接口规范、开发文档、示例插件和可运行的测试案例，以便后续增加网站时不必修改软件主体。

### 刮削代理

支持直连、HTTP/HTTPS 代理、SOCKS5 代理等适用配置。

允许全局默认代理和单个站点独立配置。

搜索、详情页面和图片请求都应遵循对应插件的网络配置。

## 六、影片信息来源管理

每部电影和电视剧可以关联多个刮削来源。

需要记录：

- 来源网站名称
- 站点内影片编号
- 影片详情页完整 URL
- 元数据最近更新时间
- 对应的刮削插件

在影片详情页展示来源信息，支持点击后在浏览器中打开对应网址。

多个网站提供同一部影片信息时，应合并为同一影片实体，保留各自的来源记录，避免重复创建影片。

不同来源的评分应保留来源标识，不得与用户个人评分混淆。

---

## 七、全局搜索与组合筛选

提供统一的搜索入口。

电影和电视剧需要支持：

- 关键词
- 影片名称及别名
- 多分区筛选
- 多标签筛选
- 标签包含任一、同时包含、排除
- 年份范围
- 评分范围
- 观看状态
- 收藏状态

“其他”分类主要按文件名、文件夹及目录位置进行搜索，不要求影视元数据。

筛选结果支持普通播放和随机播放。

**筛选后的随机播放必须针对全部符合条件的结果，而不只是当前分页已经加载的内容。**

可保存常用筛选条件，形成智能片单。

---

## 八、全局随机播放系统

采用**洗牌式随机顺序播放**。

基本规则：

1. 根据用户配置确定候选集合
2. 每个符合条件的随机对象以相同概率参与洗牌
3. 随机打乱全部对象形成播放队列
4. 按队列顺序播放
5. 本轮内不重复播放相同随机对象
6. 队列结束后默认停止，允许用户主动重新洗牌

随机单位：

- 电影：一部影片
- 电视剧：一整部剧
- 其他：一个视频文件

支持选择全局随机范围：

- 电影
- 电视剧
- 其他
- 其他分类中的特定文件夹

支持从当前筛选结果直接创建随机队列。

需要展示当前队列、播放位置、上一项、下一项、重新洗牌等操作。

播放队列应能够在程序重启后恢复。

**随机播放不能被用户评分、喜好、推荐权重改变概率。猜你喜欢与随机播放必须是两个独立系统。**

## 九、个性化猜你喜欢

基于个人观影行为生成可解释的影片推荐。

主要依据：

1. 用户个人评分（1～10）
2. 影片标签
3. 观看时长
4. 收藏行为
5. 想看记录
6. 不感兴趣反馈
7. 女演员偏好

推荐原则：

- 个人明确评分比普通观看时长更重要
- 收藏属于正向喜好信号
- 不感兴趣属于明确负向信号
- 想看可反映潜在兴趣
- 同一电视剧的多集观看不应使该电视剧过度影响偏好
- 为陌生类型保留一定探索机会
- 提供推荐原因
- 用户可以主动调整推荐结果

推荐分成两种：

**本地猜你喜欢**：从已入库的电影和电视剧中推荐，可以直接播放。

**新片猜你喜欢**：从第三方网站新发现、但还未入库的影片中推荐，展示来源和对应网址。

第一版可使用可解释、可调试的规则推荐模型，不强制使用大型语言模型或在线 AI 服务。

不得用随机排列冒充个性化推荐。

## 十、影片发现中心

软件能够通过支持新片发现功能的刮削脚本，定期获取网站最新收录的影片。

支持：

- 手动刷新
- 自动定期刷新
- 按来源网站、分类筛选
- 根据个人偏好排列推荐内容
- 新片去重
- 标注本地已入库影片
- 标记想看、不感兴趣
- 查看推荐原因
- 查看刮削来源与详情页网址

需要区别：

- 影片上映时间
- 网站收录时间
- 软件首次发现时间

同一部影片出现在多个网站时，只展示一个影片实体，但保留所有来源链接。

**软件只提供推荐和来源网址，不提供自动购买、自动下载或资源获取任务。**

用户自行决定是否访问来源页面及后续购买或下载。

## 十一、个人观影统计

提供独立的「观影统计」页面。

### 观看记录规则

**实际观看时长严格超过 10 分钟，即超过 600 秒，视为一次有效播放。**

暂停、拖动进度条不能虚增观看时长。

每次播放会话应保存实际观看时长和对应媒体信息。

区分：
- 播放会话数量
- 有效播放次数
- 累计实际观看时长
- 观看过的不同影片数量

不需要计算或展示完播率。

### 个人评分

采用 **1～10 分整数评分**。

- 个人评分可以为空
- 评分可修改
- 未评分不能视作零分
- 个人评分独立于网站评分
- 电影与电视剧支持评分
- “其他”分类不强制支持个人评分

### 统计内容

至少支持：

- 累计观影时长
- 有效播放次数
- 观看过的电影数量
- 观看过的电视剧数量
- 日、周、月、年观影趋势
- 影片类型偏好
- 标签偏好
- 个人评分分布
- 重复观看最多的影片
- 最常观看的演员、导演
- 年度观影报告

统计结果可以作为猜你喜欢的输入，但统计页面与推荐页面应保持独立。

## 十二、女演员墙

**电影模块必须提供专门的「女演员墙」子 Tab，并且只展示女演员。**

使用刮削得到的演员资料建立演员索引，支持同一演员的多名称、别名合并及去重。

女演员卡片展示：

- 演员照片
- 演员姓名
- 已入库参演影片数量
- 已评分影片数量
- 个人平均评分
- 可点击进入演员详情

演员详情页展示：

- 头像和基本信息
- 参演影片海报墙
- 已入库影片数量
- 个人平均评分
- 影片筛选和播放入口
- 对该演员影片创建随机播放队列

### 喜好程度定义

**女演员喜好程度 = 用户对该演员参演的已评分电影的个人评分算术平均值。**

例如，对演员 A 参演的三部影片分别评分 9、8、10，则该演员喜好程度为 9.0 分。

规则：

- 仅计算用户的个人评分
- 未评分影片不参与平均
- 同一影片多个版本只计算一次
- 不同演员可以共享同一部影片的评分
- 无有效评分时展示“暂无个人评分”

### 排序方式

至少包含：
- 个人平均评分降序
- 已入库参演影片数量降序
- 已评分影片数量降序
- 姓名排序

支持设置最低已评分影片数量，例如至少 1、3、5、10 部，以避免单部高分影片导致排名失真。

对于演员性别缺失或无法确定的记录，不能直接推断为女性；允许手动补充或修正资料。

女演员偏好可参与猜你喜欢，但不影响随机播放概率。

## 十三、Windows 桌面 UI 设计

软件需要现代化、精致、统一的桌面界面。

整体风格建议：

- 深色影音中心风格
- 真实影片海报为主要视觉内容
- 清晰的视觉层级
- 合理的留白与信息密度
- 流畅的悬停、选中和切换反馈
- 高质量的图标、封面、加载和空状态
- 支持窗口缩放及常见 Windows 分辨率

不要使用大量粗糙方框、占位 SVG 或只有文字的简单后台页面作为最终 UI。

### 主导航

采用多 Tab 结构：

1. 首页
2. 电影
3. 电视剧
4. 其他
5. 影片发现
6. 观影统计

另外提供始终可访问的：
- 全局搜索
- 随机播放
- 设置

### 首页子 Tab

至少包含：

- 为你推荐
- 继续观看
- 最近入库
- 想看

### 电影页面

包含：
- 影片海报墙
- 女演员墙

### 电视剧页面

包含：
- 剧集海报墙
- 剧集详情
- 季与集列表
- 观看进度

### 其他页面

包含：
- 左侧文件夹层级导航
- 右侧当前目录的视频缩略图
- 文件搜索与播放操作

### 影片发现页面

包含：
- 为你发现
- 网站最新收录
- 来源筛选
- 想看清单

### 观影统计页面

包含：
- 数据概览
- 趋势图
- 影片偏好
- 评分分布
- 年度统计

请先建立统一的 UI 设计规范，再实施各个页面，避免不同模块呈现完全不同的设计风格。

## 十四、数据安全与基础体验

必须考虑以下要求：

- Windows 本地离线媒体播放
- 主流视频格式与字幕支持
- 播放进度保存和恢复
- 本地媒体数据持久化
- 海报与视频缩略图缓存
- 大型媒体库的查询和浏览性能
- 导入任务失败恢复
- 文件操作安全
- 第三方脚本隔离
- 本地数据备份与恢复
- 日志、异常处理及基础诊断

不要要求用户必须注册云账号才能使用本地核心功能。

联网只应用于需要刮削、更新、发现新片等功能的场景。

## 十五、开发顺序

请按阶段推进，不要所有功能同时编写。

### 第一阶段：可用的桌面媒体库

完成：

- 技术选型
- Windows 应用基本框架
- 统一 UI 布局
- 电影、电视剧、其他三个媒体类型
- 文件夹扫描和媒体导入
- 基础视频播放器
- 视频缩略图生成
- 本地数据持久化

验收条件：用户可以启动程序、导入真实视频、浏览目录、播放视频并关闭重启后继续使用。

## 已确认的实现默认值

- 用户已确认优先接入 TVmaze；不要求云账号。
- 产品名暂定 Lumen；Windows 10/11 x64；开发 Python 3.11–3.13。
- 默认导入引用原文件，自动整理需先配置并确认目标规则。
- 目录拖入一次处理一个根目录，包含全部子目录。
- 个人评分筛选明确作用于个人评分；站点评分在来源中独立显示。
- 日期统计使用运行机器的本地日，数据库会话保存 UTC 时间。
- 有效播放严格 >600 秒；不展示完播率；播放结束标记仅用于剧集恢复。
- 自动发现仅在程序运行时执行；网站不提供收录日期时显示未知，不用上映日期替代。
- 演员 gender=unknown 或缺失时不进入女演员墙，可人工修改。
- 同标题与年份用于跨来源的保守默认匹配；存在来源绑定冲突时停止并要求人工确认。
