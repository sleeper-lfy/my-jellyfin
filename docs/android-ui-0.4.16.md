# Android UI 规范与 0.4.16 回归

0.4.15 的真实使用截图暴露了三类问题：把竖向封面强制裁成横图、横排控件没有留白，以及系统队列列表不限制长标题。此前缺少实际封面图的页面截图没有发现裁剪问题。本次规范把这些要求落实到共用组件和实际布局测试。

## 尺寸和间距

| 项目 | 规则 | 对应实现 |
| --- | --- | --- |
| 基础间距 | 8dp；页面左右 16dp；大分区 24dp | `MediaStyle.SPACE / PAGE / SECTION` |
| 点击区域 | 按钮、下拉、主要输入至少 48dp 高；独立图标按钮至少 48dp 宽 | `MediaStyle.TOUCH`，表单与操作行 |
| 同行控件 | 相邻控件间距 8dp，输入框占剩余空间 | `MediaStyle.LinearRow` |
| 窄屏表单 | 不把输入、选择和文字操作挤进同一行；发现搜索的应用操作单独一行 | 发现工具面板 |
| 自适应宽度 | 卡片按实际测量的可用窗口重排；不借物理屏幕宽度推断分屏宽度 | `ResumeStrip / PosterGrid` |
| 层级 | 页面标题 24sp、分区 20–22sp、正文 14–17sp、辅助 12–13sp | 原有主题与共用文字样式 |
| 长标题 | 续播和队列最多两行，末尾省略；无障碍说明保留完整标题 | `QueueAdapter`、续播标题 |

工具栏图标使用居中绘制的 `quiet` 按钮，避免空文字但仍保留左侧 compound drawable 的偏移。筛选偏好、观看状态、并排年份和下拉输入使用同一横排间距。Chip 换行间距统一为 8dp。

## 图片规则

继续观看展示**具体续播视频文件的缩略图**：读取 `resume.thumbnail`，由服务端返回该文件的视频帧／NFO 缩略图地址；禁止回退到 `work.cover` 海报。旧服务端没有缩略图字段时，明确显示“暂无视频缩略图”占位，不把海报冒充视频缩略图。

媒体作品封面与视频缩略图均使用 `FIT_CENTER` 等比完整显示；竖向、横向和超宽图片都可留深色边，不裁掉任何一边。继续观看维持横向卡片和独立文字区，续播按钮位于标题旁，避免覆盖图片主体。头像等身份照片仍可裁剪以适配头像容器。

继续卡片最大宽度 336dp，按真实滚动窗口留下 16dp 后续卡片提示。窗口缩小时会重算卡片及图片区尺寸，首张图片整体位于视口内，不能通过隐藏卡片右边来伪装适配。

## 手机队列

条目最多两行，最低高度 72dp；列表独立滚动，不让一个长标题占据整个窗口。播放、上移、下移、移除四个操作等宽，间隔 8dp。队列使用宽度随窗口的底部对话框；说明最多两行，列表通过布局权重吸收剩余高度，短窗口不依赖固定屏幕高度减法。

## 验证与限制

`AndroidLayoutRegressionTest` 使用非私人合成封面。先让作品海报和视频缩略图指向不同 HTTP 地址，验证实际加载的是续播文件缩略图且不会请求海报；旧服务缺字段时验证占位。再分别用竖向、超宽和 16:9 图片实际绘制，检查四条彩色边缘均仍存在。测试同时测量 320dp、393dp 工具区和 640×393dp 短窗口队列，使用真实长标题检查省略、按钮尺寸、间距与边界。`ApprovedUiTest` 和既有导航测试继续覆盖续播身份、时间、筛选和主要操作。

实际 View 截图输出到本次 UI 预览目录。合成封面和虚构标题只用于回归，不写入用户资料库；这些截图不证明真机解码、网络或播放性能。
