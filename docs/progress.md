## 已知范围与限制

- 首版为文件夹级导入任务，一次处理一个根目录；没有并行批量导入队列或后台常驻系统服务。
- 插件协议支持独立 actors 能力，但 UI 通过影片详情抓取演员，没有单独演员站点资料更新页。
- TVmaze 以最新 ID 目录表示“新收录候选”，不提供确切站点收录日期时保存未知；默认一次 12 部，可配置数字索引页和多个分类。不宣称每次同步全部网站历史。
- 标准命名或共同外部标识可可靠匹配；没有共同标识的同名同年作品可能需人工确认。未识别剧集不会默认为第一集。
- 外挂字幕保留文本和时间，复杂 ASS 特效、蓝光菜单、DRM、ISO 不在当前播放验收范围。
- 大库采用批量查询和分批卡片，已验证 1 万作品；尚未对百万级库做 FTS/增量索引专项优化。
- 备份功能覆盖数据库；视频、图片缓存及插件需额外复制数据目录，不提供完整视频打包备份。
- 便携版构建脚本已提供；尚无代码签名、安装向导和自动更新器。
- 尚未进行 Windows 人工视觉与可用性验收，因此不声称界面和媒体兼容性已达到最终发布品质。

## 混合来源视频解码增强（2026-10-22）

Android 0.3.0 将 Media3 替换为 LibVLC 3.7.7，内置软件解码库，覆盖 ARM64、ARMv7、x86、x86_64。默认硬件优先并允许软件回落；播放核心报错时自动使用软件模式重试一次，保留位置。新增手动解码模式、音轨、字幕选择及原生进度条；失去音频焦点或进入后台时暂停。手动解码偏好持久化。播放器通过回环流式转发器访问当前文件，服务端密钥仅用于上游请求头，不暴露在原生播放器 URL 中。

电脑导入扩展 RM/RMVB、ASF、VOB、OGV、MTS、3GP/3G2、DIVX、F4V、M2V/M2T。8 组真实编码样本的导入和 HTTP 解码验证通过，Python 完整回归 **58 项通过**。这些样本在 Linux FFmpeg 验证，不代表 Android 真机解码已验证。LibVLC 的格式覆盖优于只依赖系统解码器，但高码率、4K/10-bit、HDR、复杂字幕仍需逐设备验收；没有承诺所有文件均流畅播放。

构建工具更新为 Gradle 8.11.1、AGP 8.10.1、compile SDK 36；保持最低 API 26、target API 35。开发签名不变，versionCode 升至 2，可覆盖安装先前测试版。

Android `assembleDebug`、`lintDebug` 和 `testDebugUnitTest` 全部成功；5 项流式转发测试通过，覆盖完整字节、Range/HEAD、服务端鉴权、字幕、路径限制、拒绝重定向和关闭。APK v2 签名与 ZIP 对齐检查通过，并确认与上一测试版使用相同签名、包含四种架构和 LGPL 许可文件。Lint 无错误，仍有 target SDK、备份声明和字符串国际化建议。通用 APK 约 96 MiB。

## JavBus AV 女优头像来源（2026-10-27，源码）

新增 `plugins/javbus-actors`：按姓名请求 `/searchstar/<姓名>`，优先解析搜索结果中的公开头像；搜索页只有演员链接时，再逐条请求演员页读取头像，每次任务最多 12 个候选。插件只返回姓名、来源页和头像地址，不返回视频、磁力或下载链接，也不编造来源未提供的许可与署名。宿主继续按 manifest 精确域名、代理、TLS、GET 和请求预算执行，并只跟随声明域名内最多 3 次重定向。

实际使用中 `/searchstar/<姓名>` 返回 302 时，旧宿主会直接拒绝。现在宿主在每次跳转后重新校验协议、主机与用户信息，跨域跳转和超过 3 次的重定向仍会失败；插件同时支持站点把搜索重定向到唯一演员页的情况，按页面 canonical 地址和女优头像生成候选，不把影片封面冒充头像。

真实使用反馈 `/searchstar/<姓名>` 返回 302 到 `https://www.javbus.com/doc/driver-verify?referer=...`，即站点反自动化验证页。据此宿主请求改为携带常见浏览器的 `User-Agent`、`Accept`、`Accept-Language` 头（仅请求头，不执行交互式验证），并只跟随声明域名内最多 3 次重定向、跨域跳转拒绝；插件在命中验证页时自动改为经 `r.jina.ai`（第三方 Reader，域名已入 manifest 权限）读取同一地址并解析 Markdown，验证页再次出现时如实报错。本轮本机经 `127.0.0.1:7897` 代理实测：国内直连站点正常，但该代理节点对 github、tvmaze、javbus、r.jina.ai 的 TLS 握手均被切断，浏览器 UA 与 Reader 方案仍未能在线复测；测试使用本地 fixture 与本地 HTTP 服务。用户此前直连可到达站点（收到 302），建议应用内清空代理直连重试或修复代理节点。未重新打包 EXE / APK，未发布 Release。

## JavDB / JavRate 演员头像与 curl 抓取（2026-10-28，源码）

`javrate-actors` 请求 `/actor/list/<姓名小写>`，默认经 `r.jina.ai` 转发以绕过 JavRate 的 Cloudflare 验证；只解析“共找到AV女優”到“查找:”之间的结果卡片，排除“本月出道女優”侧栏，读取 `/actor/detail/<id>.html`、姓名和 `picture.avking.xyz` 头像。列表 `_s.webp` 会升级为同目录 `_l.webp`：实测麻里梨夏为 44,426 字节、**800×1280**，抽样其他演员为 991×1366、1366×2048，最高 **1920×2882**。Reader 限流、Cloudflare 拦截或未配置代理时明确报错，不伪造候选。

抓取层改用系统 `curl` 优先、httpx 回退：Python httpx 经 `127.0.0.1:7897` 访问 JavDB、JavBus、GitHub 均在 TLS 握手被切断（`UNEXPECTED_EOF`），而系统 curl 经同一代理返回 200/301。curl 不跟随重定向，仍由宿主逐跳校验协议、域名和用户信息；禁止 shell、限制 `=http,https`，无代理时 `--noproxy '*'` 忽略环境变量，并沿用大小与时间预算。无 curl 的环境继续使用 httpx。
