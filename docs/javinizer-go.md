# Javinizer-Go 按需刮削

Lumen 可使用 Javinizer-Go 查询影片元数据。组件仅在查询时启动，结束后退出，不启动 Web 服务、浏览器或 FlareSolverr，也不建立另一套影片数据库。适用于电影与 VR 电影，按番号查询；按姓名搜索演员头像继续使用原来的头像插件。

## 安装与使用

1. 打开 **设置 → 按需刮削引擎**，点击 **下载组件并启用**。下载在现有后台任务中执行，可以在主窗口查看进度或停止。
2. 下载困难时，从[官方 v1.6.6 发布页](https://github.com/javinizer/javinizer-go/releases/tag/v1.6.6)下载 `javinizer-windows-amd64.exe`，再点击 **选择已下载的官方组件…**。仅接受相同版本与 SHA-256 的官方组件。
3. 按需调整来源顺序和代理。`inherit` 跟随“通用 / 数据安全”中的默认刮削代理；留空为直连。点击 **保存引擎设置**。
4. 在影片详情点击刮削，选择 **Javinizer-Go · 番号刮削（按需运行）**。窗口会优先从已有标识、标题或视频文件名识别番号；选中候选后更新当前作品。也可以在导入窗口或电影分区规则中选择此引擎。

支持 `IPX-535`、`IPX_535`、`ipx00535`、`300MIUM-123`、`FC2-PPV-1234567` 等形式。带番号的文件名可以直接粘贴；包含多个不同番号时要求重新输入。引擎不提供片名或标签搜索，不用于电视剧、Fans 和其他视频。

## 来源、缓存与图片

默认依次尝试 R18.dev、LibreDMM、JavBus，首个成功来源返回完整候选后停止。还可选择 JavDB、Jav321、FC2。各站收录范围与网络可用性不同；来源返回其他番号时拒绝采用该结果。

资料查询缓存保存在 Lumen 原有 SQLite 的 settings 表中，默认有效期 168 小时，最多 256 条 / 8 MiB；有效期设为 0 可停用缓存。清除缓存同时解除来源冷却，不删除已入库资料、评分或图片。缓存上限约束的是缓存记录内容，SQLite 文件与备份的实际大小还受数据库页和历史写入影响。

401、403、429 会记录来源、主机和错误，并将该来源冷却 5 分钟，然后尝试下一来源。所有来源失败会明确报错；所有来源均未收录才显示无结果。更换引擎不会自动解决登录验证、站点拒绝或代理不可达。

资料先保存，图片在数据库写事务之外下载，避免阻塞其他资料操作。封面、头像、剧照下载失败分别记录到任务页；再次刮削可重试缺失图片。下载图片使用引擎代理，DMM 图床附带固定 Referer。返回的图片地址必须属于内置主机白名单。字段锁定、个人评分、播放记录和自选海报继续保留；电影资料可合并到原 VR 作品。

站点评分只接收已明确量表的 0–10 分数。LibreDMM 的原始 `review` 字段没有声明量表，当前不写入站点评分，避免将五星分数当成十分制。

## 进程与组件

- 当前固定 **Javinizer-Go v1.6.6 / Windows x64**，组件 59,761,664 字节（57.0 MiB）。不随 Lumen 安装包预装。
- SHA-256：`762a81d660438c4abd83fbd0bf7a31374803b8f4d0d09381127e6b65d12e3004`。下载和每次运行前都校验。
- 组件目录：`<Lumen 数据目录>/engines/javinizer-go/1.6.6/`，附上游 MIT 许可证。
- 同时最多一个查询进程，来源默认超时 60 秒，可设 15–180 秒。取消、超时和输出超限都会终止进程树；Windows Job Object 在父应用退出时也回收进程。
- 设置 Go 软内存目标 96 MiB，Windows 进程树硬上限 256 MiB。软目标不等于实际峰值；空闲时没有引擎进程。
- 仅使用 `scrape --scrapers <单个来源> --output json --no-browser`，不传视频路径，不调用整理、改名或移动命令。JSON 模式不支持 `--force`，刷新通过 Lumen 清除缓存控制。
- 继承环境中的 `JAVINIZER_*` 与代理变量不会影响查询；配置和工作目录为每次任务的独立临时目录，任务结束后清理。

这是宿主内置的受信任组件接口，JS 插件仍只有原先的受限 HTTP GET 能力，不能启动任意可执行文件；第三方脚本不能使用保留的 `javinizer-go` ID。

## 本轮验证

2026-11-04 在 Windows 上使用官方 v1.6.6 与已有代理，完整适配层查询 `IPX-535` 成功，返回影片资料、演员和海报地址，耗时约 17 秒；第二次命中 Lumen 本地缓存。带诊断日志的一次原生查询测得峰值工作集 56.1 MiB、峰值私有提交 78.9 MiB。查询结束后临时目录已清理，未创建引擎影片数据库，没有残留引擎进程。这是单样本测量，各来源与影片的耗时、峰值会有差异。

152 项相关回归通过，包含真实父子进程的取消 / 超时回收、来源回退、缓存、下载校验、设置与手动匹配、字段锁定、图片失败和并发编辑保护。全量回归还发现一项既有的软件更新测试接口不匹配：`tests/test_desktop_updates.py` 传入 `size_resolver`，而原有 `updates.check()` 不接收该参数。
