# 数据库升级与诊断

## 自动升级保护

数据库使用 SQLite `PRAGMA user_version`，当前版本为 2。版本 1 建立既有基础表，版本 2 增加喜欢字段并完成已有的个人偏好统一；没有版本号的旧库从 0 按序升级，原有偏好迁移标记仍被尊重。

升级前，在写锁保护下将已提交数据备份至数据目录 `backups/schema-旧版本-to-新版本-唯一编号.sqlite`，包括尚在 WAL 中的已提交数据，并校验备份。备份失败就停止升级。所有迁移步骤、结构变更和版本号在同一事务内提交；失败全部回滚，保留升级前备份供恢复。

打开版本高于当前程序支持范围的数据库，会拒绝写入并提示使用较新客户端。版本号已为当前版本但缺少关键表或字段时，不会把它当成旧库悄悄重建。后台连接也必须使用已升级的库。

这项保护从本次客户端开始生效。此前发布的旧客户端没有版本拦截逻辑，不能保证它们安全打开未来的新数据库；不要降级打开已升级资料库。数据库升级前的副本可用于恢复原版本客户端。

恢复备份时先校验版本，旧库在临时副本内升级，不改原始备份；通过后先备份当前库再恢复。自动备份不包含视频、图片和插件。升级备份目前不自动删除，确认新版稳定后可自行归档。

测试覆盖：无版本旧库、版本 1、新建数据库、历史 v0.4.9/v0.4.10 初始化器生成的样本、升级中断回滚与重试、备份失败、未来版本拒绝、恢复旧备份。历史样本使用真实旧版本初始化代码和合成媒体记录生成，来源及哈希见 `tests/fixtures/schema/provenance.json`，不包含用户资料库。

## 一键诊断包

设置 → 通用 / 数据安全 → **导出诊断包（先预览）…**。

在后台收集报告后展示完整 JSON 内容，由用户选择保存 ZIP。报告包含程序和数据库版本、系统类型、播放后端、FFmpeg 可用性、作品/文件/任务数量，以及少量显示设置。

日志采用固定名单，每个文件最多读取末尾 256 KiB，只保留日志时间、级别统计和受限程序模块的堆栈行号。诊断包不包含原始日志消息、数据库、影片标题、媒体路径、Cookie、访问密钥、代理地址或插件配置。它适合初步排障；具体异常消息如有必要应单独检查并脱敏。

导出不自动上传或发送给任何人。ZIP 先写临时文件，成功后替换目标；写入失败保留原有文件。
