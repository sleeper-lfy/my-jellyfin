# JavBus / JavDB 搜索与详情返回 403

HTTP 403 表示服务端拒绝当前请求, 发生在 HTML 解析之前。可能来自浏览器验证、登录状态、网络出口或站点访问策略, 不能据此断言是解析器失效, 也不保证换一个刮削软件即可解决。

## 新的请求方式

JavBus / JavDB 的影片及演员插件在自动模式下使用 curl_cffi 的 Chrome 兼容请求。每次请求在独立短时进程中执行, 完成、超时或取消后释放, 不加载 WebEngine、浏览器窗口或 AI 模型, 不增加后台常驻服务。其余插件默认仍使用标准 curl / httpx, 可按插件选择兼容或标准模式。

兼容方式保留精确域名、HTTP(S)、TLS 校验、代理、最多三次重定向、4 MB 资料 / 10 MB 图片上限和取消机制。每一步跳转由宿主检查, 不自动扩大网络权限。它改善浏览器 TLS / HTTP 请求特征的兼容性, 不执行页面 JavaScript, 无法保证通过交互验证。未安装兼容组件时明确提示, 不静默退回原本失败的请求。

## 在 UI 中处理

1. 打开 **媒体管理 → 分类规则与来源 → 安装与检测影片来源**, 选择 JavBus 或 JavDB。
2. 点击 **站点访问设置**。默认请求模式为“自动”; 可以切换“浏览器兼容请求”或“标准 curl / httpx 请求”。设置 → 第三方插件中也有相同入口。
3. 先用一个已知编号执行“检测来源”。失败时区分验证页、需要登录、拒绝访问和请求过频, 不再仅显示一个 HTTP 数字。站点以 200 返回验证页时也不会被当作成功资料。
4. 如果仍要求验证或登录, 点击“在浏览器打开站点”, 在浏览器中正常完成。浏览器与插件应使用相同网络出口; 浏览器能访问不代表 Lumen 默认直连也能访问, 检查默认刮削代理与插件独立代理。
5. 如需要站点会话, 在你自己浏览器的开发者工具 → Network 中找到成功页面请求, 将其请求头中的 Cookie 内容和 User-Agent 填入窗口, 保存后重新检测。不要把这些值发送到聊天或问题反馈中。Cookie 仅填写内容, 不含 Cookie: 前缀。

Cookie 使用掩码显示, 保存到本机数据库的独立宿主设置, 不传给 JS 插件, 不放在子进程命令参数或来源检测结果中。只发送到配置绑定的精确协议、主机、端口; CDN、其他来源、不同端口、HTTP 降级和更换站点地址均不携带原会话。卸载来源或“清除会话”会清除保存的会话; 数据库备份会包含这些设置, 诊断包不包含。

## 自动任务行为与验证范围

遇到 401 / 403 或验证页时仍会尝试已配置的备用来源。全部失败且只有这些阻断错误时进入待确认, 不自动反复重试相同会话; 修改代理 / 会话后可手动重试。429、服务器错误和普通网络错误保留重试行为。

测试使用真实的本地 HTTP 服务和实际 curl / httpx / 兼容子进程, 验证会话、跨域隔离、错误分类、响应上限、跳转与取消。当前云环境不允许连接 JavBus / JavDB, 因此没有宣称真实站点已恢复; 最终可用性需要在用户的网络和有效会话下检测。修改尚需随新安装包发布, 旧版 Release 不会自动获得新请求引擎。
