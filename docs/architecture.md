# 系统架构

桌面单进程 UI → 领域服务 → SQLite / 文件系统 / libmpv 播放器（Qt Multimedia 兼容回退）。耗时导入、刮削、图片和文件整理由 QThread 执行，每个工作线程使用独立 SQLite 连接；WAL 与 busy timeout 避免共享跨线程连接。每次只运行一个变更型后台任务，播放和浏览可继续。

## 模块

## 数据模型

SQLite `user_version` 标记 schema 版本。旧库升级先备份，再在单一事务内按序迁移；失败回滚，未来版本拒绝写入。恢复旧备份先迁移临时副本。详见 [数据库升级与诊断](data-safety.md)。

`works` 是电影/整剧/其他视频实体；`favorite` 为唯一的喜欢／收藏状态，与 `disliked` 互斥；`liked` 保留旧版兼容，API 作为收藏别名，推荐不重复加权。旧独立喜欢一次性合并，旧备份先在副本上迁移；`files` 保存版本、季集、路径、校验和和恢复位置。`name_keys` 保存历史标题/别名索引，`external_ids` 保存带类型的外部唯一标识。`sources` 保存插件/来源内编号/完整网址/独立评分/更新时间/站点收录时间。`sessions` 是每次播放的实际时间，`activity` 按本地日归档实际观看秒数。`tasks` 记录导入、匹配、整理和刮削结果。`settings` 保存队列和插件/分区配置；`lists` 保存智能片单筛选表达式。

随机队列是作品 ID 的 SystemRandom 洗牌，完整筛选结果一次参与、无偏好权重，索引持久化，末尾停播。电视剧恢复优先未完成且有位置的集，否则第一未完成集。整剧所有集完成后从第一集开始。

推荐通过个人评分、收藏、想看、负反馈、封顶观看时间构建标签/女演员偏好。显式评分权重大于观看时间；同一电视剧多集累计仅提供封顶一个观看信号。每第五位可插入一个无既有偏好的探索作品。不会将推荐权重传入随机模块。

PC 播放器在界面线程采样单调时钟，将累计会话快照交给独立数据库连接保存，不在采样回调等待写锁。片尾状态与位置采用同一顺序保护；用户手工重置写入较新的状态时间戳。退出持续争锁时保存本地恢复文件，下次重试不会重复累计或回滚较新位置。服务端直接观看会话仍使用原有同步领域接口，在请求工作线程运行。

## 文件安全

默认导入是建立引用，不移动源文件。整理须用户手动确认或先明确启用分区自动整理。目标同名拒绝覆盖。复制到目标目录唯一临时文件，flush/fsync，校验源与目标 SHA-256，然后无覆盖发布（Windows 使用同目录无覆盖 rename；Linux 使用同目录硬链接），最后才删除源文件。每一状态落库，重试只操作日志中记录的文件。空间不足/权限错误/目标冲突保留原文件。

备份恢复只恢复数据库，不移动或删除视频。媒体目录迁移可通过 PC“修复路径”在完整指纹校验后更新原记录，保留进度和书签；数据库备份不包含视频文件。

## 插件边界

脚本只能输出 GET 请求计划和元数据；宿主校验精确域名、协议、用户信息、大小和请求预算，只跟随声明域名内最多 3 次重定向、跨域跳转拒绝，不向脚本暴露秘密或本地文件。插件请求优先由系统 curl 发送，无 curl 时回退 httpx；两者共用同一权限与预算校验，curl 仅用于兼容按 TLS 指纹拦截 Python 客户端的站点。代理可全局/单插件覆盖。JS 进程使用无回调 QJSEngine；这不是允许任意原生插件的系统。Qt 引擎本身仍应随安全更新升级。
